# M4 部署與自動化維護 — 規格草案（高風險，須使用者核准）

狀態：草案　風險：高　依賴：M1、M2（上線前必須完成）　雲端供應商**尚未決定**，下列應用層需求與供應商無關

## 目的
讓系統能在公網上長期自我維護：自動更新、自動重啟、自動備份、異常通知，且每項都可驗證。

## 設計（需求層，供應商待定）
- **容器：** `Dockerfile`（非 root、唯讀檔案系統、僅資料目錄可寫、固定相依版本）；`docker-compose` 內含應用與 Caddy。
- **HTTPS：** Caddy 自動申請／續期憑證；HTTP 一律轉址 HTTPS；HSTS；安全標頭（CSP、`X-Content-Type-Options`、`Referrer-Policy`、`Permissions-Policy`）；請求本體上限與 M2 一致。
- **網路：** 防火牆只開 80／443；SSH 只允許金鑰且限定來源 IP；關閉密碼登入。
- **自動更新：** 系統安全更新自動安裝，必要時於凌晨自動重開；Dependabot 發相依更新；CI 跑 `pip-audit`、`bandit`、全部測試。
- **部署：** GitHub Actions：測試全綠才部署；部署後健康檢查失敗自動回復舊版。
- **自動重啟：** 程序崩潰自動拉起。
- **備份：** SQLite 持續複寫到儲存桶（Litestream 或同等）；圖片目錄每日同步；儲存桶啟用版本控制與保留期；**每季還原演練腳本**自動還原到暫存環境並比對筆數與檔案雜湊，輸出報告。
- **監控與通知：** 外部服務每 5 分鐘檢查 `/api/v1/health`，異常通知；磁碟 >80% 通知；費用預算警示；**每月健康報告**（備份次數、封鎖次數、磁碟、異常事件）寄給指定負責人。
- **機密：** 環境變數或雲端機密管理，repo 內不得有金鑰；`.env` 已忽略。

## 驗收條件
1. 本機以 compose 啟動後：`curl http://` 被 301/308 轉到 HTTPS（測試環境用本機憑證）；回應含 HSTS 與 CSP。
2. 殺掉應用程序 → 30 秒內自動恢復且 `/health` 回 200。
3. 超過本體上限的請求在代理層被拒（413），不進到應用。
4. CI：任一測試失敗或 `pip-audit` 發現高危漏洞 → 不部署。
5. 部署一個故意壞掉的版本 → 健康檢查失敗後自動回到上一版（在測試環境演練）。
6. 備份：寫入 N 筆資料後刪除本機資料庫，從備份還原，筆數與圖片雜湊完全一致（腳本化並有報告）。
7. 容器以非 root 執行；資料目錄以外唯讀（以 `docker inspect`／寫入嘗試驗證）。
8. repo 以祕密掃描工具檢查無金鑰。
9. 每月健康報告可由腳本產生並寄出（測試環境用假寄信）。

## 規格挑戰
- 自動重開機與自動更新可能在你操作時中斷服務 → 限定凌晨維護時間窗。
- 備份本身含個資 → 儲存桶需加密、限權、限制公開存取；還原演練只能在受控環境。
- 6 人規模是否需要自動回復舊版這套機制？成本與價值需權衡（可降級為「手動一鍵回復」）。
- 跨境：區域若在境外，需法遵確認並於隱私說明載明。

## 修訂 1（依使用者回覆）：Q9 AWS，區域放台灣
查證結果（來源見 PROGRESS）：AWS **亞太（台北）區域 `ap-east-2`** 已於 2025 年 6 月開放，有 3 個可用區。
- 建議區域：**台北 `ap-east-2`**（資料留在台灣、延遲最低，對個資與使用者最有利）。
- ⚠ **尚未確認的事（上線前必須在 AWS 官方的區域服務清單核對）：** Lightsail 是否在台北區域提供、各服務在台北區域的價格（可能與東京不同）。若 Lightsail 在台北不可用，改用 EC2 小型機型加 EBS，規格不變。
- 備份儲存桶：同樣放台北，跨 3 個可用區已有基本耐久性；**不建議把備份複製到其他區域**，除非使用者同意個資跨境（會與資料留台灣的目標衝突）。
- 免費額度（查證）：2025-07-15 之後的新帳號是「$100 起的試用額度＋6 個月免費方案」，兩者先到者為準，不再是 12 個月免費主機；**到期後費用要自行負擔**，請在 AWS Budgets 設警示。
- 備選區域：東京 `ap-northeast-1`（服務最完整、成熟）；僅在台北缺少必要服務時才考慮，並須通過個資跨境確認。
- 規格其餘部分與雲端供應商無關，維持原設計。

- 主機：一台小型 Compute Engine VM 跑 compose（應用＋Caddy）；⚠ 我印象中免費額度的小型 VM 只限美國區域，台灣區域應視為要付費。
- 備份：Cloud Storage 儲存桶（同區域、版本控制、保留期、禁止公開存取）；Litestream 持續複寫 SQLite、圖片目錄每日同步。
- 監控與告警：Cloud Monitoring 的 uptime check 打 `/api/v1/health`，異常寄信；磁碟用量告警；預算警示（Billing Budgets）寄信。⚠ 設定細節核對官方文件。
- OCR（之後）：Cloud Vision，經 `OCRProvider` 介面接入，屬獨立工作，需使用者的專案與憑證。
- **每月健康報告與「轉人工待處理超過 7 天」提醒**：由應用的排程工作產生，經 `Notifier` 寄 Email。⚠ **應用程式自己寄信需要寄信服務的帳號或機密**（例如 Gmail 應用程式密碼、或某寄信服務的金鑰），**由使用者提供，我不會自行申請或編造**；在取得前以「寫入記錄檔」的預設通知器運作並在測試中驗證內容。

**沒有網域時怎麼辦（HTTPS 的前提）：**
- 設定檔 `public_hostname` 為參數；**實作與本機測試不需要網域**（測試用本機憑證）。
- 上線前一定要有主機名稱，選項：① 購買網域（建議）；② 暫時用公用的萬用 DNS 服務把 IP 轉成主機名稱（可行但依賴第三方、不適合正式長期使用）；③ 改走 Tailscale，不上公網。
- **在有主機名稱之前，不得對公網開放服務。**

**驗收條件新增：**
10. 同一個映像不改程式碼即可在本機、GCP、AWS 設定下啟動（以環境變數切換備份目的地與通知器）。

## 修訂 3（台北 2026-10-21）：免費額度部署選項
使用者詢問能否部署在 Google 免費額度。查證（**第三方整理，未取得 Google 官方頁面，上線前須核對**）：常駐免費額度為 1 台 e2-micro、30GB 標準硬碟、每月 1GB 北美出站流量，**僅限美國 us-west1／us-central1／us-east1**；Cloud Storage 免費 5GB 同樣只在這三區。
- 影響：**免費＝資料放美國（跨境）**。收據含統編等個資，須由使用者決定可否接受並在隱私說明載明；要留台灣就用預設的 `asia-east1`（需付費，價格尚未查）。
- 實作：`deploy/gcp/provision.sh --free-tier`（e2-micro、pd-standard 30GB、us-central1，並輸出跨境警告；拒絕非免費區域）；真正執行必須設定 `BUDGET_AMOUNT`（超額會計費，一定要預算警示）；`startup.sh` 在記憶體 <2GB 時自動加 1GB swap。
- 建議流程：先用免費美國 VM 演練容器行為（尚無真實個資、無跨境問題），正式上線前再決定區域；切換區域只需改 `REGION`／`ZONE` 參數，程式不用改。
- e2-micro（約 1GB 記憶體）是否撐得住 app＋Caddy＋排程器（＋Litestream）**未實測**。
