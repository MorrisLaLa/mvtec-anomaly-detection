# F2 現場人員介面簡化 — 規格草案（中風險；含一項需使用者核准的 M1 修訂，見下）

狀態：草案　依據：使用者回饋「示範介面工程現場人員不容易直覺使用」（2026-10-14）
使用者已選：**最難的是第一次設定**；日常流程要簡化成 **拍照→確認→送出**；綁定要**同時支援「點連結」與「掃 QR」**。

## 設計原則
現場人員在戶外、單手、可能戴手套、沒時間讀說明。每個畫面只做一件事，按鈕大、字大、用詞是工地的話。

## 1. 第一次使用（目標：不需要打任何字）
1. 管理員傳連結（或給 QR）。現場人員點連結或用手機掃 QR。
2. 頁面自動配對：顯示「正在設定這支手機…」→「設定完成，王志明你好」（姓名由伺服器的裝置名稱決定，**不再有「選姓名」畫面**）。
3. 直接進首頁。
- **PIN 改為選用**（建議預設關閉；在「設定」可開啟）。理由：PIN 只是手機本機的解鎖，不是安全邊界（稽核 A14）；手機遺失靠管理員撤銷金鑰。⚠ 待使用者確認。
- 保留一個很小的備用入口「連結打不開？輸入設定碼」（手動輸入短碼，給 QR／連結都失敗時用）。
- 目前的「綁定長金鑰」畫面改為管理員／除錯用，不放在首次流程裡。

## 2. 日常流程：拍照 → 確認 → 送出
- **首頁只有一個最大的按鈕：「拍收據」**（開相機）。其下兩個較小的：「從相簿選」「沒有收據」。
- **確認畫面預設只有：** 收據縮圖、金額（有電子發票 QR 時可留空，系統自動帶入）、店家（可不填）、工程案件（預設為目前案件，點一下可換）。其餘（分類、單據類型、日期、簽名）收在「更多選項」裡，預設自動帶入。
- **送出後**顯示全螢幕結果，不是只有一條會消失的提示：
  - 已送出：「✓ 已送出」
  - 沒網路／等 Wi‑Fi：「已存好，連上 Wi‑Fi 會自動送出」＋「現在用行動網路送出」按鈕
  - 被退回：「這張被退回：<原因>」＋「重新拍一張」
  - 主管確認中：「主管確認中，通過後不用再做什麼」

## 3. 用語（工地的話）
| 現在 | 改成 |
|---|---|
| 案號 / 公司案號 / 業主案號 | 工程案件 |
| 無單據 | 沒有收據 |
| 待同步 | 等待送出 |
| 等待 Wi‑Fi | 等 Wi‑Fi（省流量） |
| 待審核 | 主管確認中 |
| 已記錄 | 已送出 |
| 已退回：重複報銷… | 這張被退回：這張發票已經報過了 |
| 分類 | 用途（自動帶入，可改） |
| 憑證 / 簽收憑證 | 簽收單 |
錯誤訊息一律說明「怎麼辦」，不顯示系統代碼（如 HTTP 422）。

## 4. 版面
- 可點的東西至少 48 px 高、字至少 16 px；主要動作放在畫面下半部（單手拇指）；高對比（戶外日光）。
- 一個畫面一件事；返回與送出的位置每個畫面一致。
- 示範控制列只出現在示範版，**正式版不得出現**。
- 主管／管理員的審核畫面維持獨立入口，只有該角色看得到。

## 驗收條件（Playwright，真實後端）
1. 首次使用：開啟配對連結後**零次鍵盤輸入**即進入首頁；姓名來自伺服器；網址列的配對碼被清掉。
2. 配對連結：使用過一次後再開 → 顯示「這個連結已失效，請向管理員索取新的」；過期同理。
3. 日常：從首頁到送出，**選好照片後只需再點 1 次「送出」**（有 QR 時不需填任何欄位）。
4. 確認畫面預設可見的輸入欄位 ≤ 3 個；分類、類型、日期、簽名在「更多選項」內。
5. 預設畫面不得出現舊術語（上表左欄）；掃描整頁文字比對。
6. 所有按鈕與可點項目高度 ≥ 44 px（量測）；內文字級 ≥ 16 px（量測）。
7. 送出後的結果卡片四種狀態各有測試（已送出／等 Wi‑Fi／被退回含原因／主管確認中）。
8. 正式版頁面不含示範控制列與模擬伺服器程式碼。
9. 既有前台行為測試（Wi‑Fi 策略、方案 B、審核）全部維持通過；Wi‑Fi 策略下仍然「行動網路零連線」。

## 之後可再加（不在這一版）
- 瀏覽器端即時讀取 QR 預填金額：Android 的 Chrome 有 `BarcodeDetector`，iPhone 沒有；需要另外引入函式庫。
- 語音或更大字級的「長輩模式」。
