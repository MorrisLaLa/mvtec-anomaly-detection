# 夜間作業規則（無人值守）

排程：台北時間 22:00–04:00 每小時整點啟動一次（共 7 次），**凌晨 5:00 之後不得開始新工作**。
每次啟動都是全新的工作階段，只靠 repo 內的文件接續進度。

## 每次啟動的固定步驟
1. 先讀 `expense-backend/PROGRESS.md`、`docs/APPROVALS.md`、`docs/WINDOWS.md`；**不要重新探索整個專案**。
2. 若台北時間已過 05:00，或 `PROGRESS.md` 最後一筆標示「卡住待回報」，立刻結束，不做任何事。
3. 依 `docs/WINDOWS.md` 找出第一個尚未完成的視窗，只做那一個。
4. 工作中隨時存檔：完成一個小單元就提交並推送到分支 `claude/expense-reporting-system-a4vamf`（不要建立新分支、不要建立 PR）。
5. 結束前一定更新 `PROGRESS.md`（做了什麼、測試結果、下一步），提交並推送。額度用盡被中斷時，已推送的內容就是進度。

## 授權閘門（不可違反）
- **高風險模組（M1 身分與授權、M2 收件與儲存、M3 審核與匯出、M4 部署與備份）：**
  只有 `docs/APPROVALS.md` 中該模組的規格被使用者勾選「已核准」，才可以寫程式。
  未核准時只能產出或修訂 `docs/specs/` 內的規格草案，**不得自行核准、不得改 APPROVALS.md 的勾選**。
- 中、低風險工作（辨識、分類、前端）可以在規格已寫入 `docs/specs/` 後直接做。
- 遇到需要使用者決定、真實資料、金鑰、刪除既有資料、修改既有資料庫 schema 的事：停下來，寫進 `PROGRESS.md`（標「卡住待回報」），結束，不要猜。

## 工作方式
- 單線依序，不並行開 agent；一律先寫測試、測試先紅、再實作、測試全綠才算完成；不得為過關而改測試。
- 自我修正迴圈最多 5 次，超過就停下來記錄。
- 不得提交任何金鑰、真實統編以外的個資或 `.env`。
- 不得更動 `main`，不得合併、不得建立 PR。
- 不得建立或修改任何排程。
